## Open (actionable)

### Reliability / correctness

- **[B][Sync] Push/pull asymmetry of `created_at`/`updated_at` (CONFIRMED).** Pull carries both and restores them (`SyncEngine::presentForWire:94-95`, `PullApplier:169-176`); the push payload (`PushDrainer:49-55`) does NOT carry them, and `NodePusher::persistMerged:134-159` does not set them → the cloud stamps the receive time: a desktop-created node loses its true `created_at`, and `updated_at` is overwritten with the receive time — the very “future timestamp re-shards / burns the pull cursor” hazard the pull side defends against. LWW is not affected (`perFieldUpdatedAt`). Fix: carry both in push; `created_at` INSERT-only, `updated_at` by LWW — symmetric with pull. **✅ CLOSED W1.4 (`8eb07cda`):** both are in the push payload; `NodePusher::persistMerged` stamps from the wire on INSERT, `created_at` is untouched on UPDATE, `updated_at` = `max(local, incoming)`. Audit clarification: `updated_at` = the cloud pull cursor (`ChangesController:45`) → “updated_at LWW” is implemented as `max`, not blind-take-incoming (otherwise the cursor regresses and an ahead puller misses a change).

### Performance (sub-100ms)

- **[B][Perf] Navigating into a node sends 95 queries, 23 of them duplicates (the user’s debug bar, 2026-07-29, SQLite dev).** The earlier entry “the duplicates are real but cheap, folded 19 → 8” referred to the FULL PAGE contract; on the navigate-into-node contract they are alive and different. Repeated: the recursive CTE `OutlineSubtree.php#59` ×3 (the node’s full subgraph, three times per request), `NowInSlugResolver.php#47` ×4 (over different id sets — that is, each reader asks for ITS OWN set, exactly the shape in which `TypeGlyphResolver` surfaced 46×), `ScopeChainResolver.php#83/#144/#181` ×~6, `NodeKindResolver.php#54` ×2 (an identical `exists` scan), `MentionMetaResolver.php#74` ×2, `NodeViewFilter.php#70` ×2. On SQLite this is 12.4 ms of db out of a 115 ms request, so time-wise it is not urgent now — but the “how many TIMES we asked” axis costs more on PG with RTT, and the `OutlineSubtree` CTE is linear in the subgraph. Measure with `by_caller.php` with `$CONTRACT='nav'`; fix with per-request memoization on the resolvers, but ONLY after grepping for “is there a tool that writes the input and renders the output in the same request” (the rule from `NowInSlugResolver`, which is exactly the one that must NOT be memoized). **[fix]**

### Maintainability

- **[C][SoT] `ParentTitleResolver` reads ONLY the scalar `parsed_meta.parent_id` and does not ask the `child_of` edge.** The same policy hole that state had, but on the parent axis: breadcrumbs and the canonical path come from the edge, while the two-line picker row (“hermes in Projects”) comes from the mirror, so on a desync they will name different parents. Readers: `Search`, `MentionsController`; the same shape in `SidebarGroupPresenter:169`, `Graph.php:70`, `VaultLayoutSynchronizer:86`. **The difference from the state fix, and why I did NOT take it:** there both maps were already in memory (the edge map loads in q5), and the flip cost nothing; here edge-first is a NEW bulk `child_of` query on suggest surfaces, that is, a decision with a cost, not a cleanup. **User decision 2026-07-29: we do not pay queries for this.** The mirror on the parent axis stays canonical for the two-line picker row; the divergence from the breadcrumbs is accepted. Trigger for revisiting — a complaint “the picker row shows the old parent”, that is, a real desync, not a hypothetical one.

### Security / UX

- **HTML sanitizing of node title/content — defense in depth; there is no sink today.** Today it is XSS-safe by construction: not a single `{@html}` in the Svelte tree (title/content are always Svelte-escaped), no server-side markdown→HTML (content is stored/served as markdown text and parsed only in the editor), and the body editor’s `html:true` goes through the schema-sandboxed ProseMirror `DOMParser` (drops `<script>`, ignores `onerror`, a detached parse does not execute). The only stringly-HTML sink — the `MentionExtension` `mention_inline` render rule — is closed by escaping (`renderMentionChipHtml`, `lib/editor/mentionChipHtml.ts`); the title after the fix = plain text + `[[slug]]` tokens (a JSON text node, not an HTML parse). BUT: any future rendering of title/content as **raw HTML** (public share, server-side preview, email digest, export to HTML, RSS) must sanitize — DOMPurify on the client / a purifier on the server. Guard candidates: an arch/lint rule that forbids `{@html}` on node data, + a sanitize wrapper on the first raw-HTML sink. Trigger for the fix — the first feature that renders content as HTML. **[fix P6]**

### Code diverges from Foundation (2026-10-03)

The decisions are in `specs/foundation/design.md` and `text.md`; here is only where the code does not follow them yet. Each item is fixed together with its consumers: a token is introduced at the same time as every place moves onto it, otherwise the concept has two sources.

- **Brand and assets.** `public/favicon.ico` is someone else’s blue “A.” mark, not O_. Filament falls back to it too: `AdminPanelProvider` has no `favicon` and no `brandLogo`, and primary is `Color::Amber`, not `--brand`. The desktop icon (`public/icon.{png,ico,icns}`, `resources/icons-source/*`) has a gray underscore; per design.md §1 it is orange: regenerate via `scripts/gen-icons.sh`. `AppLogo.svelte` is imported nowhere — delete it. `AppLogoIcon.svelte` draws the mark through `<img>`, bypassing `OveryMark`. The dev variant is chosen by different conditions: Blade — `Environment::isDev() || app()->isLocal()` (`app.blade.php:51`), Svelte — `import.meta.env.DEV`.
- **Font.** Instrument Sans is loaded from Bunny (`vite.config.ts:30-34`, `@fonts` in `app.blade.php`) and sits second in `--font-sans`, which is declared twice (`app.css:19`, `:129`). Remove the loading and the font from the stack; keep one `--font-sans`. There is no `--font-mono`, and `docs/show.svelte:387` declares its own mono stack.
- **Icons.** Iconify pulls icons from the network on first display: a desktop without a network is left without icons. An offline collection is needed (`@iconify-json/fluent` + `addCollection`, or a build of the used subset). `size-4` is on 78 icons versus 26 with `size-5`, while the default is `size-5`. `components.json` declares `iconLibrary: lucide` and `tailwind.config.js` — neither exists in the project.
- **Color.** There are no success, warning, info and focus tokens, so `SyncIndicator.svelte:73-78` builds statuses from the palette, `InputError.svelte:13` writes `text-red-600`, bypassing `--destructive`, and `SuccessAlert.svelte:17` and `TwoFactorSetupModal.svelte:245` take two different greens. About 64 raw palette colors in components; the largest: `VaultShell.svelte:448,460` (a repeat of `--editor-fade-surface` through `bg-neutral-150 dark:bg-neutral-900`), `Chip.svelte:142`, `DeleteUser.svelte:26-28`, `AppearanceTabs.svelte:28-36`. The dark `--sidebar-primary` (`app.css:223`) is white, like its foreground: contrast 1.00, comma syntax. Nobody reads `--sidebar` (`app.css:179,229`) and `--chart-1..5`. The default border is set twice: `app.css:116-124` (`--color-gray-200`) and `app.css:241-244` (`border-border`). Graph colors live in four places (`graphTheme.ts:46-57`, `NodeGraph.svelte:120-123` and `:648-657`, `ChipConnector.svelte:36-38`); the `--ng-*` fallbacks diverge from `app.css`.
- **Contrast below AA.** Table — design.md §5: `muted-foreground` on `muted`, `accent` and `secondary`, `muted-foreground/60`, `destructive` as text and under the button’s white text, `brand` as text and icon on white, the `input` border (1.26 where 3 is needed).
- **Layout.** Breakpoints as numbers in JS: `SidebarProvider.svelte:41` (768), `ContactForm.svelte:24` (639), `VaultPreview.svelte:234,262,291,296` (975 and 640), `docs/show.svelte:263,280` (768). `@container` is declared in `NodeSummary.svelte:866` and `CardHeader.svelte:17`, but no child class reads it.
- **Typography.** Arbitrary font sizes in primitives: `Field.svelte:31` (`text-[11px]`), `Button.svelte:20` (`text-[0.8rem]`), `NavItem.svelte:469`, four in `NodeGraph.svelte`. The `<style>` of `docs/show.svelte` has its own scale of 12 `font-size` values.
- **Layers and shadows.** There are 14 z-index values, among them `z-[60]`, `z-[100]`, `z-[110]`, `9999` and `2147483647`; there are no scale tokens. `SelectContent.svelte:31` and `TooltipContent.svelte:23` build the shell bypassing `surface-panel`, `NodePicker.svelte:271` sets `shadow-md`, `CaptureToast.svelte:24` — `shadow-2xl`. `surface-scrim` blurs everything under a modal (`backdrop-blur-xs`), while `nickture-interface` requires a solid backdrop: either remove the blur or record an exception in design.md.
- **Radii.** Bare `rounded` — 48 places. `Button.svelte:19-24` (`rounded-[min(var(--radius-md),10px)]`) and `input-group-button.svelte:8,10` compute the radius their own way.
- **Motion.** There are no duration and easing tokens. Timings are scattered across CSS, Svelte transitions (`fly` 260 and 300, `fade` 150, 200 and 500) and GSAP (`choreograph.ts`, `demoAutoplay.svelte.ts`). Svelte transitions and the view transition ignore reduced motion; `motion-reduce:` is not used once.
- **Accessibility.** There is no global `:focus-visible`: focus is set 65 times in 22 files in different ways (`ring-2`, `ring-3`, `ring-[3px]`, `outline-2`), plus 18 `outline-none`. ESLint does not show Svelte a11y warnings (`svelte/valid-compile` is not enabled); only `svelte-check` sees them, and `components/ui/*` is excluded from ESLint.
- **Components.** shadcn primitives in `components/ui/` were edited in place. Commits per folder, counting the addition: dialog 11, command 9, dropdown-menu and checkbox 6 each, sidebar and select 5 each, tooltip, popover and input 4 each, spinner, input-otp, field and button 3 each. Our own primitives live inside `ui/`: `chip` (26 commits), `segmented-tabs`, `section-header`. First compare each folder with upstream and work out which edits are still needed. Move the needed ones into wrappers outside `ui/`, and move our own primitives out of `ui/` too.
- **There is no state sandbox.** `/mocks/n` (`routes/web.php:114-116`) is a “test page” stub. What it should be — design.md §13.
- **The screens have not been audited against the `nickture-interface` checklist.** The next pass after Foundation: the vault screens, MetaPanel, QuickCapture, Spotlight, settings, the landing page.
